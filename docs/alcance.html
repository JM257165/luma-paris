Luma Event Scraper

Scraper automatisé qui découvre chaque jour les nouveaux événements tech et ai sur Luma (lu.ma), sans API officielle, pour alimenter des dashboards, newsletters ou alertes.

Objectif : 1 exécution par jour, sans intervention manuelle Stack : Python stdlib + GitHub Actions Statut : v1 terminée

Périmètre v1

Dans le périmètre

  • Consulter les catégories tech et ai
  • Couverture multi-villes (≥ 5 coordonnées configurables)
  • Déduplication entre exécutions par api_id
  • Persistance : état des événements vus, CSV maître, CSV quotidien des nouveautés
  • Exécution programmée 1 fois par jour (cron / GitHub Actions)
  • Relances avec backoff en cas de panne réseau

Hors périmètre (v1)

  • Scraping des listes de participants (nécessite une session)
  • Notifications push (Slack / Telegram / e-mail)
  • Enrichissement des données des hôtes
  • Filtrage sémantique par mots-clés
  • Interface / dashboard de visualisation
  • Déduplication sémantique (uniquement par api_id)

Exigences non fonctionnelles

IDExigence
RNF-1Aucune dépendance à une API officielle ni clé d'API
RNF-2Respectueux du serveur : pauses aléatoires, pas de concurrence agressive
RNF-3Résilience aux changements de schéma : log + continuer
RNF-4Portabilité : Python standard, sans dépendances externes obligatoires
RNF-5Coût : exécutable sur un runner gratuit (GitHub Actions free tier)
RNF-6Traçabilité : champ first_seen sur tout nouvel événement

Risques et atténuations

RisqueImpactAtténuation
L'endpoint non documenté change ou cesse de répondre Élevé Journalisation détaillée + revue périodique du payload brut
Mesures anti-bot (limitation de débit, blocage d'IP) Moyen Pauses entre requêtes, pas de concurrence, backoff
Changements des Conditions d'utilisation de Luma Moyen à élevé Revue juridique avant tout usage commercial ; ne pas conserver de données personnelles
Biais géographique de l'endpoint Faible à moyen Interroger plusieurs villes ; surveiller la couverture
